# GOALBALL LIVE v2

실행: https://parabiomech.github.io/GOALBALL_LIVE/

v1 보관: https://parabiomech.github.io/GOALBALL_LIVE/v1.html

외부 라이브러리나 LLM 호출 없이 브라우저에서 사용하는 골볼 실시간 기록 프로그램입니다.

## 기록

날짜·경기명·전반 왼쪽/오른쪽 팀을 등록합니다. 팀별 선수 6칸에서 번호는 필수, 이름은 선택입니다. 현재 출전 선수 1~3명을 체크하고 L/C/R을 지정합니다. 출전 선수의 포지션은 중복될 수 없습니다. 후반을 선택하면 코트의 팀 위치가 자동으로 바뀝니다.

선수 → 일반투구/페널티투구 → 코트에서 출발·릴리스·도착 클릭 → 투구 기록(Enter) 순서입니다. 저장 후 기술유형 F/C/SB/LB와 골(G)·파울 L(L)·파울 H(H)을 각각 선택합니다. 같은 버튼은 선택을 해제합니다. 각 선택은 독립적으로 저장되며 다음 투구로 이어지지 않습니다.

출전 선수 버튼은 등록 순서와 관계없이 L·C·R 위치에 고정됩니다. 최근 기록은 최신순 전체 목록이며 목록 안에서 스크롤하고 투구를 눌러 수정할 수 있습니다. 기술유형은 시간 입력 없이 선택합니다. 골·파울 결과 이벤트에는 분·초를 수기로 입력할 수 있습니다. 먼저 시간을 입력하고 결과를 선택하거나 결과 선택 후 시간을 수정하면 저장됩니다. 빈칸은 미입력이고 분 0~999, 초 0~59를 허용합니다. 이벤트 이력은 `postEvents`, 결과 시간은 `resultTime`에 저장합니다. 이전 기록의 기술 시간은 불러오기·내보내기에서 보존합니다.

최근 투구를 눌러 수정·저장한 뒤 기술유형과 결과·시간을 보완할 수 있습니다. 위치 수정 시 기존 시간과 이력은 유지됩니다. 직전 변경은 되돌리기로 복원할 수 있습니다.

## 선수교체와 포지션 변경

‘선수교체 · 포지션’ 버튼은 등록 창을 엽니다. 출전 체크가 바뀌면 `substitution`, 계속 출전 중인 선수의 L/C/R이 바뀌면 `positionChange`로 기록합니다. 둘 다 바뀌면 두 종류의 이벤트를 각각 저장합니다. 이름만 보완하거나 벤치 선수의 포지션만 수정하면 경기 중 변경 이벤트로 집계하지 않습니다.

변경 시간(분·초)은 선택 입력입니다. 교체 전후 명단, 이벤트 종류, 전·후반, 수기 시간, 실제 입력 시각, 전체 몇 번째 투구 후 변경했는지를 보관합니다. 변경 이벤트는 투구 수와 득점률의 분모에 포함하지 않습니다. 결과지 아래 펼침 목록과 JSON에서 확인할 수 있습니다.

## 코트와 아웃

가로 x=0~180, 세로 y=0~90이며 1단위는 10cm입니다. 아래쪽이 실제 경기 벤치입니다. 각 골대의 오른쪽이 1구역입니다. 왼쪽 골대는 아래부터 위로 1~6, 오른쪽 골대는 위부터 아래로 1~6입니다. 가운데 선·골대는 파란색입니다.

아웃 입력은 기존 캔버스 여백의 연한 표시를 활용합니다. 출발·릴리스는 코트 안에 찍고, 도착 단계에서 1구역 바깥의 오른쪽 아웃 또는 6구역 바깥의 왼쪽 아웃을 누릅니다. 모바일과 키보드 입력을 위해 도착 단계에만 코트 아래 좌우 아웃 버튼도 표시합니다. 버튼은 상대 골대 기준의 아웃 방향을 저장합니다. 아웃은 `{out:'left'|'right', goalSide:'left'|'right'}`로 저장하며 x/y 거리 좌표를 저장하지 않습니다. 아웃 표시로 이어지는 선은 방향 표시일 뿐 실제 도착 거리나 공 추적 결과가 아닙니다. 아웃 도착점은 가우시안 밀도 계산에서 제외하며 알려진 출발·릴리스 좌표만 사용합니다.

## 결과지

경기 구간(전체/전반/후반), 팀, 선수, 도착 코스(1~6/오른쪽 아웃/왼쪽 아웃), 기술유형(전체/F/C/SB/LB/미선택), 이벤트를 조합할 수 있습니다. 팀 합계는 선수 필터만 제외하고 나머지 조건을 적용합니다. 교체·포지션 변경 목록은 경기 구간과 팀 필터를 적용합니다.

각 팀이 왼쪽에서 오른쪽으로 공격하도록 정리합니다. 실제 오른쪽 코트에서 공격한 기록은 x=180-x, y=90-y로 180도 변환해 골대 기준 1~6구역을 일치시킵니다. 결과지는 팀 기준 도식이므로 실제 벤치 위치와 구분됩니다. 수집 좌표 원본은 바꾸지 않습니다.

σ=7단위(0.7m) 가우시안 위치 밀도와 출발→릴리스 점선, 릴리스→도착 실선을 함께 표시합니다. 모든 표시 그림에 공통 색상 기준을 적용합니다. 구역과 아웃의 빈도·비율은 해당 그림의 전체 투구를 분모로 하며, 1~6구역과 좌우 아웃 비율의 합이 100%입니다. 득점률은 골/전체 투구입니다.

## 버전과 저장

v1은 `v1/` 및 `GOALBALL_LIVE-v1-backup.zip`(로컬)에 보관하며 원본 GitHub 커밋은 `9e0eee2`입니다. 파일 체크섬은 VERSION_HISTORY.md에서 확인할 수 있습니다.

v2 JSON은 schemaVersion 5, appVersion 2이며 자동 저장 키는 `goalball-live-v5`입니다. v1의 `goalball-live-v4`를 읽어서 가져오되 원본 키는 삭제하지 않습니다. 기존 이름·좌표·전후반·기술·결과를 유지하고 없던 수기 시간은 미입력으로 둡니다. 구역 번호는 새 골대 기준으로 계산합니다. 더 오래된 두 점 형식도 기존 변환 규칙으로 가져올 수 있습니다. v2의 새 기록은 v1에 자동 반영되지 않습니다.

기록은 사용 중인 브라우저에 저장되며 GitHub로 전송되지 않습니다. 메뉴의 파일 저장·불러오기로 백업하거나 다른 기기로 옮기세요. v2 JSON은 v1에서 지원하지 않습니다.

## 검증 및 배포

`node verify.cjs`: 이름 없는 명단, 교체/포지션 변경/혼합 변경, 이벤트 시간과 편집 보존, 골대 기준 구역과 전후반 정규화, 거리 없는 아웃과 필터·빈도, v1 데이터 보존을 확인합니다.

GitHub Pages는 main 브랜치의 루트에서 배포합니다. root의 index.html·app.js·styles.css·.nojekyll과 v1.html 및 백업 ZIP을 함께 게시합니다. v1.html은 build_v1.py로 원본 CSS·JavaScript를 포함해 만든 단일 실행 파일입니다. 원본 파일은 로컬 v1/와 백업 ZIP에 보존합니다.
